Documentation

Install, configure, automate, and understand OmniTerm.

Installation

From release to first agent.

Download the DMG and run Install OmniTerm.command. The installer copies the app to Applications, creates the CLI launchers, starts OmniTerm in the background, and registers MCP with installed providers.

$ omni mcp doctor
$ omni agents add .
$ omni

Settings and startup

Background by default, configurable from the menu bar.

Choose OmniTerm Settings… from the menu-bar icon. Changes apply immediately and are saved to ~/.omni/settings.json. Starting the app, logging in, or reopening an already-running app never reveals the terminal or Settings window; only Open OmniTerm or the global shortcut does.

CLI essentials

A useful command surface, not cron syntax.

+

Create

omni agents add . discovers project instructions and opens a prefilled wizard.

▶

Run

omni agent NAME run starts an interactive provider session immediately.

↻

Resume

omni resume RUN-ID opens the exact Claude or Codex session in a new tab.

$ omni --help
$ omni agents
$ omni agent my-agent
$ omni runs
MCP integration

Available in new Claude and Codex sessions.

OmniTerm registers a local stdio adapter named omni. The native app stays the sole scheduler and state writer while providers receive a constrained scheduling toolset.

Privacy & security

No new cloud between you and your agents.

OmniTerm adds no analytics, account, remote API, or listening TCP service. Provider CLIs retain their own authentication, network, and privacy behavior.
